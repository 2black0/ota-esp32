# OTA ESP32 IoT Sensor Hub

A robust and modular **MicroPython project for ESP32** that supports:

- 🌐 **Over-the-Air (OTA) firmware updates** from a GitHub repo
- 🌡️ **Environmental monitoring** via DHT11 (temperature & humidity)
- 📏 **Ultrasonic distance sensing** via SRF04
- 📡 **MQTT messaging** for remote monitoring and device control
- 🔄 **Remote reset** and 🟢 **LED control** via MQTT commands

---

## 📁 Project Structure

```

OTA-ESP32/
├── LICENSE                # License file
├── README.md              # This documentation
└── project/               # Firmware source files
├── main.py            # Main application (read sensors, MQTT, OTA)
├── main.mpy           # 🔧 Compiled bytecode from main.py using mpy-cross
├── ota.py             # OTA update manager
├── version.json       # Firmware version tracking (e.g., {"version": 2})
└── wifi\_data.py       # Wi-Fi and MQTT credentials (user-defined)

```

> 💡 `main.mpy` is auto-generated by compiling `main.py` using [`mpy-cross`](https://docs.micropython.org/en/latest/reference/mpyfiles.html).

## ⚙️ Features

### ✅ MQTT Topics

| Function           | Topic                         | Description                        |
|--------------------|-------------------------------|------------------------------------|
| Publish Temp       | `esp32/sensor/temp`           | °C from DHT11                      |
| Publish Humidity   | `esp32/sensor/hum`            | % RH from DHT11                    |
| Publish Distance   | `esp32/sensor/distance`       | cm from SRF04                      |
| Publish Alarm      | `esp32/sensor/alarmstatus`    | `true` if distance ≤ 15cm          |
| Publish Version    | `esp32/version`               | Device firmware version            |
| Control LED        | `esp32/led`                   | Accepts `true` / `false`           |
| Remote Reset       | `esp32/reset`                 | Accepts `"reset"` command          |

## 🔁 OTA Firmware Update Workflow

### Files Required in GitHub Repo:

- `/main/main.mpy`: Compiled firmware (generated from `main.py`)
- `/main/version.json`: Version descriptor (e.g., `{"version": 3}`)

### How It Works:

1. `ota.py` checks `version.json` in the GitHub repo.
2. If a newer version is found, it downloads `main.mpy`.
3. The new file replaces the local `main.mpy`.
4. ESP32 reboots to apply the update.

> 🛠️ To build `main.mpy`, run:
```bash
mpy-cross main.py
```

## 🚀 Setup & Flashing

### 1. Flash MicroPython Firmware

```bash
esptool.py erase_flash
esptool.py --chip esp32 --port /dev/ttyUSB0 write_flash -z 0x1000 esp32-xxxxxx.bin
```

### 2. Upload Files

Use `ampy`, `rshell`, or `Thonny`:

```bash
mpy-cross main.py
ampy put project/main.mpy
ampy put project/ota.py
ampy put project/wifi_data.py
ampy put project/version.json
```

> Don't upload `main.py` if you're using `main.mpy` for OTA (to simulate production).

## 🧪 Development Notes

* During development, test with `main.py`.
* Before releasing an update:

  1. Increment `version.json`
  2. Run `mpy-cross main.py`
  3. Push `main.mpy` and `version.json` to GitHub
* OTA will automatically apply the new version on next boot.

## 🙋 FAQ

**Q: What happens if Wi-Fi fails?**
A: The device will attempt to reconnect for 10s and reset if unsuccessful.

**Q: Is OTA secure?**
A: Not yet. Consider switching to HTTPS (with SSL) in production.

**Q: Can I use AHT10 instead of DHT11?**
A: Yes, a ready-to-use section for AHT10 is commented in `main.py`.
